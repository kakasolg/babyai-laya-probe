# seed 장부 (2026-11-18, [win] 정리)

MiniGrid / BabyAI 환경 seed를 어디에 썼는지 한 곳에 모은다. 단계별 설명은 README "단계"에 그대로 있다.
"잠금" = 코드가 그 범위를 거부한다(아래 2절). 잠근 범위는 다시 열지 않는다.

## 1. 범위

| 범위 | 용도 | 상태 |
|---|---|---|
| 0 ~ 999 | 봇 시범(학습) — 모든 과제의 "1,000판" (GoToLocal은 그중 998판, PutNextLocal 1,000판) | 학습용 |
| 0 ~ 4,999 · 0 ~ 9,999 | 11b · 11b-2 · 11b-3 시범 수 곡선(앞에서 N판) | 학습용 |
| 10000 ~ 10299 | 개발용 평가 300판(모든 과제, 모든 단계, 게임의 300판 시험 · 도움 시험 포함) | 계속 씀 |
| 20000 ~ 20299 | GoToLocal 최종 확인(6단계) | 11-15에 한 번 씀, **잠금** |
| 30000 ~ 30299 | PickupDist 최종 확인(8d) | 11-15에 한 번 씀, **잠금** |
| 41000 ~ 41299 | [cloud] 작은 CNN 등급 고르기 "새 판"(`tools/small_policy/export_levels.py`, `godot/drive/README.md`) — 저장소 밖 CPU 실험 | 한 번 씀(아껴 둔 판으로 다시 잡지 않는다) |
| 40000 ~ 40999 | [cloud]가 보드(11-18)에 "40000~41299 작은 CNN 꾸러미"로 적었다. 저장소 코드에서 40000~40999를 쓴 곳은 찾지 못했다 | 쓴 것으로 본다(보드 글 기준) |
| 50000 ~ 50039 | 게임 등급 고르기 미리 보기(`export_levels.py`의 `range(50000, 50040)`) | 한 번 씀 |
| 50040 ~ 50299 | [cloud]가 보드에 "여러 설정 50000~50299(11-16 미리 보기)"로 적었다. 저장소 코드에서는 50000~50039만 보인다 | 쓴 것으로 본다(보드 글 기준) |
| 60000 ~ 60299 | 물건 16개(9단계, `num_dists=16`) 최종용 | **열지 않음**, 잠금(11-19부터 기본 거부에도 들어감 — 2절) |
| 70000 ~ 70299 | PutNextLocal 최종 확인(10e) | 11-16에 한 번 씀, **잠금** |
| 80000 ~ 80299 | 다음 과제의 최종 확인용 | **열지 않음**, 11-19에 예약 · 잠금 |

- 퍼즐 · 드라이브 게임의 방(퍼즐 묶음 1,252방, 측정 600방)은 MiniGrid seed가 아니라 Godot `rooms.gd`의 방 생성기로 만든 것이다(`godot/drive/PUZZLE.md`). 위 표와 겹치지 않는다.
- 맥(13 · 15단계)도 개발용 10000~10099 / 10299만 썼다(`reports/stage13*.md`).

## 2. 코드의 거부 규칙과 표 대조

| 함수 | 거부하는 범위 | 쓰는 곳 |
|---|---|---|
| `probe/dump_demos.py` `guarded_seeds` | 20000 · 30000 · **60000** · 70000 · **80000**대 | `dump_demos`, `closed_loop`, 5 · 8 · 8a · 11 · 11b(GoToLocal) · 12 · 13 · 14(GoToLocal)단계 |
| `probe/stage9.py` `seeds_of` | `guarded_seeds` + 60000대(겹침) | 9단계 |
| `probe/stage10.py` `seeds_of` | `guarded_seeds` + 60000 · 70000대(겹침) | 10단계, 11b · 14(PutNextLocal), `export_godot_putnext` |

**고쳤다 (2026-11-19, [cloud], MoKa 결정).** 전에는 기본 거부(`guarded_seeds`)가 60000~60299를 막지 않아
`closed_loop`나 5 · 8 · 11 · 12 · 13 · 14단계 실행기(GoToLocal)에 `--seeds 60000-60299`를 주면 열렸다(9 · 10단계만 막았다).
이제 `guarded_seeds`가 **60000대와 80000대도 거부한다**. 9 · 10단계의 자체 검사는 그대로 두었다(겹치지만 해롭지 않다).
확인: `0-999` · `10000-10299` · `40000-40999` · `90000-90299`는 그대로 통과하고, 다섯 범위는 모두 막힌다. 경계도 막힌다(`59990-60010`).
이 범위들을 실제로 쓸 때는 지금까지처럼 **선언을 먼저 커밋하고, 그 실행에만 쓰는 플래그를 열었다가 끝나면 지운다.**

## 3. 다음 최종 확인용 빈 범위 (예약함)

**80000 ~ 80299 — 예약했다 (2026-11-19).** 저장소 코드 · 보고서 · 보드에 쓴 흔적이 없었고, 이제 `guarded_seeds`가 거부한다.
다음 과제(여러 방 · 문 · 열쇠)의 최종 확인용이다. 더 필요하면 81000 ~ 81299, 82000 ~ 82299 순서로 같은 방식으로 예약한다.
