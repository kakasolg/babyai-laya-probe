# 10단계 선언 — 옮겨 놓기 `BabyAI-PutNextLocal-v0` (돌리기 전에 커밋)

지시: 보드 스레드 c7d1bc74, 11-16 cloud-claude 글(MoKa 지시).
이 파일을 커밋한 **뒤에** 모델 실행(10b·10c·10d)을 한다. 결과를 본 뒤 아래 기준을 바꾸지 않는다.

- 코드: `probe/stage10.py`. 질문 글은 `probe/laya_rows.py` `question_putnext()`에 있다.
- 10a 원자료: `reports/stage10/stats.json`, `bot.json`, `random.json`, `fixed.json`, `fixed-reset.json`

## 1. 고정한 설계 (보드 글 그대로)

- 환경: 코드 그대로다. 8칸 방, 물체 8개(모두 다름), 걸음 제한 128(환경 기본값).
- 선택지 다섯: turn left / turn right / forward / pick up / drop.
  - 앞 넷은 8단계와 같은 순서·글이고, drop을 뒤에 붙였다.
  - 동점이면 이 순서의 앞을 고른다. 실행은 결정적(가장 높은 점수)이다.
- 상태 글: `mission:` 줄, 그다음 **`carrying:` 줄**, 그다음 GoToLocal 관측 글(그대로).
  - 들고 있는 것은 관측 `image[3][6]`(자기 칸)에서 읽는다. 환경의 `carrying`은 쓰지 않는다.
  - 10a에서 봇 15,554걸음 모두 관측에서 읽은 값과 환경 값이 같았다.
- 질문 글: 8단계 틀이다. 목표 문장과 drop 설명만 새로 정했다.
  - instructions: "A grid agent must pick up the first object named in the mission and put it down next to the second. Pick its next action from what it can see now."
  - drop: "put down the carried object in the cell directly ahead". 나머지 넷은 8단계 글자 그대로다.
- R-reset: 5·8단계 정의 그대로다.
  - key는 모델에 준 상태 글에서 지시문 줄을 뺀 것이다. `carrying:` 줄과 방향(`facing:`)이 들어 있다.
  - 다섯을 다 해 봤으면 그 key의 기록만 비우고 1순위를 고른다.
- 모델 없는 대조군: 고정 점수 forward 0.30 > left 0.25 > right 0.20 > pick up 0.15 > drop 0.10.
- seed:
  - 학습 0~999, 개발용 10000~10299(300판 전부)
  - 최종용 70000~70299는 열지 않는다(코드가 거부).
  - 20000·30000·60000대는 잠금 그대로다.

## 2. 학습 자료 (10b)

- seed 0~999 봇 시범 중 다섯 행동만 쓰는 판은 모두 넣는다. 결과는 **1,000판 전부, 12,036행**이고 뺀 판은 0이다.
  - 2~3번 줍는 판 4판(83 · 540 · 844 · 987)도 들어 있다.
- 학습 설정: english `55cf4c4`, `loss=rlcd` 기본, `shuffle_options=('choice',)`, 기본 epoch, 학습 seed 0/1/2. 9단계와 같다.
  - 체크포인트는 `~/babyai-laya-ft/putnext-s0/1/2`(저장소 밖)에 둔다.
- 10d: 같은 행에서 `carrying:` 줄만 뺀 상태 글로 s0 하나를 학습한다(`putnext-nocarry-s0`).
  - 평가도 그 줄 없이 한다(걸음 단위 + 닫힌 루프 규칙 없음 · R-reset).
- 토큰 길이 점검(가중치 없이): 전체 입력 중앙값 159, 최대 200(한도 512). 줄을 빼면 154 / 195.
  - 학습 항목 11,636 + 보정 400, 4 epoch에 갱신 728회.

## 3. 실행

| | 규칙 없음 | R-reset (`--base` = 규칙 없음) |
|---|---|---|
| Laya s0 / s1 / s2 (`putnext-s*`) | ○ | ○ |
| Laya s0, `carrying:` 줄 없음 (10d) | ○ | ○ |
| 모델 없음 (고정 점수, 10a에서 이미 실행) | ○ | ○ |

- 기준선(10a에서 이미 실행): 봇, 무작위.
  - 무작위는 판마다 `random.Random(seed)`로 다섯 행동 중 하나를 고르고, 규칙은 없다.
- 걸음 단위 평가: 개발용 판의 봇 궤적 3,518걸음.
  - 네 갈래로 나눈다. 줍기 전 이동 1,670 · 줍는 걸음 300 · 들고 이동 1,248 · 내려놓는 걸음 300.
  - 갈래는 봇의 행동과 그때 들고 있었는지로 정한다.

## 4. 지표 (분모 300)

- 성공
- **봇 걸음 2배 안 성공**
- timeout
- 살린 판 / 망가뜨린 판 (R-reset 대 규칙 없음)
- 살린 판 중 2배 안
- 막힌 칸 전진 비율
- **어디까지 갔나** (판마다 하나):
  - ① 한 번도 못 주움
  - ② 틀린 물체만 주움
  - ③ 맞는 물체를 주웠지만 끝내 성공 못 함
  - ④ 성공
- 틀린 물체를 주운 횟수
- 내려놓았다가 다시 주운 횟수(첫 내려놓기 뒤의 줍기)
- 헛동작:
  - 들고 있거나 앞에 주울 것이 없는데 줍기
  - 들지 않았거나 앞 칸이 비어 있지 않은데 내려놓기
- 망가뜨린 판 중 R-reset이 고른 줍기·내려놓기가 들어 있는 판

## 5. 미리 정한 읽기 (보드 글 그대로 — 기준은 [cloud]가 임의로 잡은 것)

Laya 규칙 없음, 세 seed 평균, **봇 걸음 2배 안 성공** 기준:
- **240판(80 %) 이상** → 두 단계 판단도 한 단계와 비슷하게 맡길 수 있다.
- **150~239판** → 부분적으로 된다. "어디까지 갔나" 표로 어느 단계에서 무너지는지 적는다.
- **150판 미만** → 이 입력·학습량으로는 안 된다.
  - 10d(들고 있는 것 줄)와 걸음 단위 일치를 놓고, 입력 정보 / 상태 표현 / 학습 자료 / 선택 능력 중 무엇으로 보이는지 적는다(추정으로 표시).

R-reset: 망가뜨린 판이 0인지, 살린 판 중 2배 안이 몇인지.

10d:
- "들고 있는 것" 줄을 뺀 쪽이 15판 넘게 낮으면 그 줄이 필요한 정보다.
- 차이가 15판 안이면 가르지 못한 것으로 적는다(seed 하나).
- 비교 대상은 같은 학습 seed인 s0의 규칙 없음, 2배 안 성공이다.
