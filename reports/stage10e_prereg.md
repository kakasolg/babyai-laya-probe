# 10e 선언 — 옮겨 놓기 최종 확인 (seed 70000~70299, 한 번만)

지시: 보드 스레드 c7d1bc74, 11-16 cloud-claude 글(MoKa 지시). 8d와 같은 절차다.
이 파일을 커밋한 **뒤에만** 최종 seed를 쓴다. 재학습은 없다.
설정은 10c와 글자 그대로 같고, 바뀐 것은 seed 범위와 출력 폴더(`reports/stage10/final/`)뿐이다.

## 0. 돌리기 전 확인 (개발용, 이미 실행함)

- 지금 코드로 Laya s0 규칙 없음을 개발용 10000~10299에서 다시 돌렸다.
  - 10c의 `laya-s0.json`과 비교해, 300판 모두 끝·걸음 수·"어디까지 갔나"가 같았다(**불일치 0판**).
  - 결과 파일은 `reports/stage10/regress-laya-s0.json`이다.
- 코드 변경은 `probe/stage10.py`의 `--use-final-seeds` 하나다.
  - 이 플래그는 70000~70299만 연다. 다른 범위를 주면 거부한다.
  - 결과는 `reports/stage10/final/`에 쓴다.
  - 실행이 끝나면 플래그를 지워 다시 막는다.

## 1. 평가 판

- `BabyAI-PutNextLocal-v0` seed 70000~70299, 300판 전부, 걸음 제한 128. 판을 빼지 않는다.
- 봇 걸음은 이 실행에서 처음 센다. 학습에는 쓰지 않는다.

## 2. 실행 (각 한 번)

| | 규칙 없음 | R-reset (`--base` = 규칙 없음) |
|---|---|---|
| Laya s0 / s1 / s2 (`~/babyai-laya-ft/putnext-s0/1/2`) | ○ | ○ |
| 10d `putnext-nocarry-s0` (`carrying:` 줄 없는 상태 글) | ○ | ○ |
| 모델 없음 (고정 점수 forward 0.30 > left 0.25 > right 0.20 > pick up 0.15 > drop 0.10) | ○ | ○ |

- 기준선: 봇, 무작위(판마다 `random.Random(seed)`, 다섯 행동, 규칙 없음).
- 공통 설정은 10c 그대로다.
  - 상태 글, 질문 글(`question_putnext()`)
  - 선택지 다섯과 그 순서
  - key = 지시문 줄을 뺀 상태 글
  - R-reset 정의
  - 결정적 실행(가장 높은 점수, 동점이면 고정 순서의 앞)

## 3. 지표 (분모 300, 10c와 같음)

- 성공
- 봇 걸음 2배 안 성공
- timeout
- 어디까지 갔나 ①~④
- 틀린 줍기, 다시 주움, 헛동작
- 막힌 칸 전진 비율
- 살린 판 / 망가뜨린 판
- 성공 판 걸음 / 봇

실패한 판은 seed 목록과 유형(①~③)만 적는다.

## 4. 미리 정한 판정 (보드 글 그대로)

- **모델 단독 재현**: Laya 규칙 없음의 **봇 걸음 2배 안 성공, 세 seed 평균이 233판(77.7 %) 이상.**
  - 근거: 개발용 평균은 251판이다. 300판 한 묶음의 표본 오차가 약 6.3판이고 두 묶음 차이는 약 9판이라, 그 두 배(18판)를 뺐다. 8d와 같은 방식이다.
  - 평균이 **240판 이상**이면, 10단계 선언의 "두 단계 판단도 맡길 수 있다" 구간이 최종 판에서도 유지된 것이다.
  - 233~239판이면 "재현은 됐지만 구간은 한 칸 아래"라고 적는다.
- **규칙 효과 재현**: Laya 세 seed 모두 R-reset 성공 **285판(95 %) 이상**이고 **망가뜨린 판 0**.
- **`carrying:` 줄 (보조, 판정 아님)**:
  - 줄 없는 s0와 줄 있는 s0의 2배 안 성공 차이를 적는다.
  - 개발용(15판)과 최종의 차이가 둘 다 15판 이상이면 "필요한 정보로 보인다(seed 하나)"로 적고, 아니면 "가르지 못함"으로 적는다.
- 기준에 못 미치면 못 미쳤다고 적는다. 원인을 찾아 다시 돌리지 않는다.
- 중간에 죽으면 같은 설정으로 이어서 끝낸다. 결과를 본 뒤 설정을 바꿔 다시 돌리지 않는다.
