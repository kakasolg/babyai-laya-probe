# 13단계 선언 — Apple Foundation Models 온디바이스 참조선, 걸음 단위만 (돌리기 전에 커밋)

지시: MoKa가 2026-11-17 맥 세션에서 "보드의 baby ai 테스트를 맥 앱으로 할 수 있나" → "간단한 것부터 하자".
학습 없음. 참조선이라 판정 기준은 두지 않는다. Host: 맥 미니.
**이 파일을 커밋한 뒤에 평가 걸음으로 모델을 부른다. 결과를 본 뒤 설명 글·질문·입력 형식을 고쳐 다시 돌리지 않는다.** 고치고 싶은 것은 적기만 한다.

코드 `probe/stage13.py`, 원자료 `reports/stage13/*.json`, 응답 캐시 `data/stage13_cache_*.jsonl`(git 밖).
모델 호출은 Kortex 저장소의 서명된 맥 프로브 앱(`probe/Sources/kortex-probe/BabyAIServe.swift`, 명령 `babyai`)을 자식 프로세스로 띄워 한다.

## 1. 이번에 하는 것 (가장 간단한 것)

- 모델: Apple Foundation Models **온디바이스**(`SystemLanguageModel.default`, macOS 27, 맥 미니). 글 입력만.
- **걸음 단위만**: 봇 궤적 1,567걸음(`data/gotolocal_eval.jsonl`, 개발 seed 10000~10299).
  맥에서 `probe.dump_demos --seeds 10000-10299 --keep-all`로 다시 만들었고, 12단계 기록과 걸음 1,567 · 대상 보임 1,330 · 안 보임 237 · 막힌 걸음 249가 같다.
- 지표(12단계와 같은 코드 `stage12.cmd_stepcheck`): 봇과의 일치(전체, 대상 보임 / 안 보임), 선택지 순서를 뒤집었을 때 답이 바뀌는 비율,
  앞이 막힌 걸음에서 forward를 고른 비율, 고른 행동 수, 형식 오류, 지연 중앙 · 95 %.

## 2. 고정한 틀

- 설명 글: `probe/stage5.py`의 EXPLAIN 글자 그대로. 세션의 instructions로 넣는다.
- 상태 글: `mission:` 줄 + 관측 글(5단계 · 12단계 글 입력과 같음).
- 질문 글: `[Observation]\n<상태 글>\n\n[Actions]\n- <선택지 1>\n- <선택지 2>\n- <선택지 3>`.
- 답 형식: `@Generable` 틀, 필드 `action` 하나, `anyOf`로 세 선택지 중 하나. `anyOf` 순서는 질문 글의 선택지 순서와 같게 둔다(뒤집기 호출에서는 둘 다 뒤집는다).
- 걸음마다 새 세션, greedy, 최대 응답 40토큰. 추론 단계 없음(온디바이스는 지원하지 않음).
- 같은 요청(모델, 설명 글, 상태 글, 선택지 순서)은 한 번만 보낸다(5단계와 같은 캐시).

## 3. 12단계와 다른 점 (비교할 때 적을 것)

- Apple API는 선택지별 점수를 주지 않는다. 고른 선택지에 1.0, 나머지에 0을 넣어 같은 코드로 채점한다. 동점 분석은 할 수 없다.
- Gemini · clef-flash는 결정 전용 API였고, 여기는 일반 글 모델에 틀을 씌운 것이다.
- 호출이 실패하면(안전 필터, 컨텍스트 초과 등) 한 번 다시 부르고, 또 실패하면 그 걸음은 형식 오류로 세고 답은 선택지 순서의 첫째로 둔다.

## 4. 이 파일을 쓰기 전에 한 호출

- 연결 확인용 1회: 평가 파일에 없는 지어낸 상태 글, 짧은 설명 글(EXPLAIN 아님). 답 형식이 오는지만 봤다.

## 5. 안 하는 것 (다음에 정함)

- 닫힌 루프(규칙 없음, R-reset), PCC(하루 한도가 공개돼 있지 않음), 아이폰, 그림 입력, 최종 seed.

## 6. 추가 선언 (2026-11-18) — 온디바이스 닫힌 루프 100판, 규칙 없음, 걸음 로그 (돌리기 전에 커밋)

지시: MoKa(11-18 맥 세션) "닫힌 루프 먼저 100판만 하고 로그를 남겨서 분석해 보면 어때?"
걸음 단위 결과(`reports/stage13.md`: 93.7 %가 forward, 막힌 걸음에서 87.2 %가 forward)를 본 뒤에 정한 것이다.

- 모델 · 설명 글 · 상태 글 · 질문 글 · 답 형식은 2절 그대로(온디바이스, 글 입력, 근거 필드 없음).
- 개발 seed **10000~10099**(앞 100판), 걸음 제한 64, **규칙 없음**(모델이 고른 행동을 그대로 둠). 5단계 `run_loop(policy="none")` 그대로.
- 지표: 5단계 `summarize` 그대로(성공, 봇 걸음 2배 안, 처음 대상 보임 / 안 보임, timeout, 막힌 칸 전진 걸음, 고른 행동 수).
- 로그: 걸음마다 seed, 지시문, 관측 글, 고른 행동, 움직였는지, 위치 · 방향, 대상이 보이는지를 `data/stage13_loop_afm-device.jsonl`(git 밖)에 남긴다.
  실패 판의 걸음 줄(행동, 움직임)은 `reports/stage13/afm-device-100.json`의 `trace`에 들어간다.
- 분석은 탐색이다(미리 정한 판정 없음). 볼 것: 실패 판이 어디서 멈추는지(벽 앞 전진 반복, 물체 앞 전진 반복, 제자리 회전 반복),
  멈춘 걸음에서 앞이 막혔다고 글에 적혀 있었는지, 성공 판은 대상이 처음에 어디 있던 판인지.
- 이 100판은 12단계 표의 300판과 분모가 다르다. 비교할 때는 같은 100판만 놓고 본다(다른 모델의 판별 기록이 `reports/`에 있는 경우).
- 선택지를 미리 빼는 규칙(막힌 앞 · 되돌리는 회전), R-reset, 근거 필드, PCC는 이번에 넣지 않는다. 이 로그를 본 뒤에 따로 선언한다.

## 7. 추가 선언 (2026-11-18) — 정해진 걸음에 한 걸음씩 돕기, 같은 100판 (돌리기 전에 커밋)

지시: MoKa(11-18 맥 세션) "20걸음에서 목표까지 못 가면 코드로 한 칸 도와 주고, 40에서 한 번, 60에서 한 번. 목표까지 얼마나 근접하는지 보자."
6절 결과(12/100, 실패 88판은 모두 막힌 칸 앞 전진 반복)를 본 뒤에 정한 것이다.

- 모델 · 글 · 답 형식은 2절 그대로, seed 10000~10099, 걸음 제한 64, 다른 규칙 없음.
- **돕기**: 20걸음, 40걸음, 60걸음을 둔 뒤에도 끝나지 않았으면 바로 다음 한 걸음(21 · 41 · 61번째)은 모델에게 묻지 않고
  전문가 봇이 지금 상태에서 고른 행동을 둔다(`help_test.py`의 A와 같은 방식: 현재 상태를 복사해 새 봇에게 물음). 판마다 최대 3번.
  봇이 세 선택지 밖의 행동을 고르거나 오류를 내면 돕지 않고 모델에게 묻는다(센다).
- **얼마나 가까운가** 두 가지로 잰다.
  - 남은 봇 걸음: 지금 상태에서 새 봇이 혼자 끝내는 데 드는 걸음 수(걸음 예산은 새로 줌). 회전과 장애물이 들어간 거리다.
  - 맨해튼 거리: 에이전트 칸에서 지시문에 맞는 가장 가까운 물체 칸까지. 성공은 거리 1이고 그 물체를 바라볼 때다.
  잰 시점: 시작, 각 돕기 직전과 직후, 끝. 판마다 맨해튼 거리의 최솟값도 남긴다.
- 지표: 성공 판수(6절의 12판과 비교, 살린 / 망가뜨린 판), 돕기 횟수별 성공, 실패 판의 시작 대 끝 남은 봇 걸음과 맨해튼 거리(중앙값, 줄어든 판 수),
  돕기 한 번 뒤 다음 돕기 전까지 남은 봇 걸음이 얼마나 줄었는지.
- 로그: `data/stage13_help_afm-device.jsonl`(git 밖), 요약 `reports/stage13/help-afm-device-100.json`.
- 미리 정한 판정은 없다(탐색).

## 8. 추가 선언 (2026-11-18) — PCC(클라우드)로 같은 100판: 규칙 없음, 그리고 20 · 40 · 60걸음 돕기 (돌리기 전에 커밋)

지시: MoKa(11-18 맥 세션) "그러면 cloud AFM으로 100판을 같은 방식으로 하면?"
온디바이스 결과(3절 12/100, 4절 44/100)를 본 뒤에 정한 것이다.

- 모델만 바꾼다: `PrivateCloudComputeLanguageModel()`(Private Cloud Compute). 설명 글 · 상태 글 · 질문 글 · 답 형식 · greedy · 걸음마다 새 세션은 2절 그대로.
  추론 단계(`reasoningLevel`)는 주지 않는다. 근거 필드도 없다.
- seed 10000~10099, 걸음 제한 64.
  1. 규칙 없음(6절과 같은 코드) → `reports/stage13/afm-pcc-100.json`, 로그 `data/stage13_loop_afm-pcc.jsonl`.
  2. 20 · 40 · 60걸음 돕기(7절과 같은 코드, 비교 기준은 1의 PCC 규칙 없음) → `reports/stage13/help-afm-pcc-100.json`, 로그 `data/stage13_help_afm-pcc.jsonl`.
- 지표는 6절 · 7절과 같다. 온디바이스와는 같은 100판을 놓고 판별로 비교한다.
- PCC는 하루 한도가 공개돼 있지 않다. 호출이 실패하면 5초 뒤 한 번, 30초 뒤 한 번 더 부르고, 그래도 실패하면 **그 실행을 멈춘다**(실패한 걸음에 답을 지어 넣지 않는다).
  멈추면 캐시에 남은 데서 이어서 돌리고, 멈춘 사실과 시각을 보고에 적는다.
- 걸음 단위 1,567걸음(순서 뒤집기 포함 약 3,100번 호출)은 이번에 PCC로 돌리지 않는다.
