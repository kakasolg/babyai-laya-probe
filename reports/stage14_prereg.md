# 14단계 선언 — 규칙의 변형 비교 (돌리기 전에 커밋)

지시: 보드 스레드 c7d1bc74, 11-18 cloud-claude 글 "MoKa 지시(11-18): 13단계 — 규칙의 변형을 비교한다".
MoKa가 11-18 이 세션에서 "규칙 변형 비교는 14단계로 합니다 … 내용은 보드의 지시서 그대로이고, 번호만 바꿉니다".
번호를 바꾼 까닭: 13단계는 맥 미니 쪽(`mac/stage13`, Apple 온디바이스 모델)이 이미 썼다.
**이 파일을 커밋한 뒤에 돌린다. 결과를 본 뒤 변형을 더하거나 정의를 고쳐 다시 돌리지 않는다.** 더 보고 싶은 것은 적기만 한다.

코드 `probe/stage14.py`(규칙 부분은 `Rule` 클래스 하나로 모아 laya 없이 읽을 수 있게 둔다 — [cloud]의 작은 CNN에 같은 정의를 쓰기 위해), 원자료 `reports/stage14/*.json`.
브랜치 `win/stage14`(main `0af8432`에서). 11b(`win/stage11b`)는 아직 main에 병합하지 않았다.

## 1. 대상 체크포인트 (여덟 개, 모두 이미 있다, 학습 없음)

| 과제 | 약한 모델 | 기준 모델 |
|---|---|---|
| GoToLocal | N=100 s0 (`n100-gotolocal-s0`, 11b) | N=1,000 s0 / s1 / s2 (`gotolocal-s{0,1,2}`, 5단계) |
| PutNextLocal | N=100 s0 (`n100-putnext-s0`, 11b) | N=1,000 s0 / s1 / s2 (`putnext-s{0,1,2}`, 10b) |

입력 · 질문 · 선택지는 각 체크포인트의 원래 설정 그대로(GoToLocal은 5단계 `LayaScorer`, PutNextLocal은 10단계 `Scorer`, `carrying:` 줄 있음).
개발용 seed 10000~10299, 300판, 걸음 제한 64 / 128(환경 그대로). GPU, laya 기본 정밀도(bf16), 살아 있는 판을 묶어 계산. 순위는 확률 내림차순, 동점이면 선택지 고정 순서의 앞.

## 2. 변형

규칙 key는 V6만 빼고 **관측 글(방향 `facing:` 포함, `mission:` · `carrying:` 줄 제외 — 지금까지의 R-reset key와 같은 `e.text()`)**이다.
"규칙이 걸린다" = 그 key가 이 판에서 이미 나왔다(V3은 바로 앞 걸음의 key와 같다). 처음 나온 key에서는 모든 변형이 모델의 1순위를 쓴다(V7 빼고).
개입 = 실제로 고른 행동이 모델의 1순위와 다른 걸음.

| | 무엇을 바꾸나 | 정의 |
|---|---|---|
| **V0 규칙 없음** | — | 늘 모델의 1순위 |
| **V1 R-reset** | 기준 | key마다 이 판에서 해 본 행동을 기억한다. 안 해 본 것 중 점수가 가장 높은 것을 고른다. 다 해 봤으면 그 key의 기록을 비우고 1순위를 고른다(지금까지와 같음) |
| **V2 무작위 선택** | 순위를 뺀다 | V1과 같되, 규칙이 걸리고 안 해 본 행동이 남아 있으면 그중에서 **균등 무작위**. 처음 나온 key와 비운 직후는 1순위. 난수 seed 0 · 1 · 2 |
| **V3 직전만** | 판 전체 기억을 뺀다 | key가 **바로 앞 걸음의 key와 같을 때만** 규칙이 걸린다. 같은 key가 이어지는 동안만 해 본 행동을 기억하고, key가 바뀌면 지운다. 다 해 봤으면 V1처럼 비우고 1순위 |
| **V4 비우지 않음** | 비우기를 뺀다 | V1과 같되, 그 key에서 다 해 봤으면 기록을 비우지 않고 **그 뒤로는 그 key에서 늘 1순위** |
| **V5 짧은 기억** | 기억을 줄인다 | V1과 같되, 기록은 **최근 8걸음**의 (key, 행동)만(걸음마다 하나씩 쌓고 9번째부터 가장 오래된 것을 버린다). 다 해 봤으면 그 key의 기록을 지우고 1순위 |
| **V6 자리 key** | 관측 대신 진짜 상태 | V1과 같되 key = (에이전트 x, y, 방향, 들고 있는 물체). 환경 내부 값을 쓰는 **특권 기준선**(실제 정책은 볼 수 없는 정보) |
| **V7 ε 무작위** | 감지 없이 섞는다 | 규칙 없음에, 걸음마다 확률 0.1로 선택지 전체(GoToLocal 3개, PutNextLocal 5개) 중 균등 무작위. 난수 seed 0 · 1 · 2 |

- 난수는 `random.Random("V2|r{seed}|{판 번호}")`처럼 변형 · 난수 seed · 판 번호로 정해진다(다시 돌려도 같다).
- V0 · V1은 이미 값이 있다(5단계 `reports/stage5/laya-s*.json`, 10단계 `reports/stage10/laya-s*.json`, 11b `reports/stage11b/n100-*-s0*.json`).
  가림 세기와 변형끼리의 짝 비교를 위해 **V0 · V1을 한 번 더 돌리고, 성공 · 2배 안 · 살린 / 망가뜨린 판이 기존 값과 같은지 확인한다.** 다르면 다르다고 적고 기존 값과 새 값을 둘 다 적는다(V2~V7의 비교는 새로 돌린 V0 · V1과 한다).

## 3. 가림 세기 (V1을 돌리면서)

규칙이 걸린 걸음(= 그 key가 이 판에서 이미 나왔을 때)마다:
- 그때의 진짜 상태가 **이 판에서 이미 지나온 상태인가.** 진짜 상태 = (x, y, 방향, 들고 있는 물체, 격자 전체의 물체 배치). 아니면 "가림"(화면만 같고 상태는 다름).
- 가림은 둘로 나눠 적는다: (x, y, 방향, 들고 있는 물체)가 처음인 경우 / 그것은 지나왔지만 물체 배치만 다른 경우(PutNextLocal에서 물체를 옮긴 뒤). GoToLocal은 물체가 움직이지 않으므로 뒤의 것은 0이어야 한다.
- 가림 걸음 수 / 규칙이 걸린 걸음 수, 가림 개입(가림이면서 1순위와 다른 행동) 수 / 전체 개입 수, 가림이 한 번이라도 있었던 판 수, 그 판들의 결과(성공 / 실패, V0 대비 살림 / 망가뜨림 / 그대로).

## 4. 지표 (변형 · 체크포인트마다, 분모 300)

성공, **봇 걸음 2배 안**, timeout, V0 대비 **살린 판 / 망가뜨린 판**, 개입 횟수(전체와 판당), 전체 걸음 합. PutNextLocal은 틀린 줍기 · 헛동작(null pickup / null drop) 수도.
판 단위 결과(끝, 걸음 수, 개입 수)를 원자료에 남긴다. 걸음별 기록(trace)은 남기지 않는다.

## 5. 미리 정한 읽기 (보드 글 그대로)

기준 모델 세 seed 평균으로, 과제마다 따로 읽는다. V2 · V7은 난수 seed 셋의 평균을 먼저 낸다. 문턱 10판은 [cloud]가 임의로 잡았다. "10판 이상"은 차이 ≥ 10.0.

1. **순위가 일을 하는가**: V1 2배 안 − V2 2배 안 ≥ 10 → "모델의 순위가 복구의 질을 정한다". 그 밖 → "안 해 본 것이면 무엇이든 비슷하다".
2. **판 전체 기억이 필요한가**: V1 성공 − V3 성공 ≥ 10 → "직전 반복만 봐서는 모자라다(좌우 번갈아 돌기 같은 것을 못 잡는다)". V5가 V1과 V3 사이 어디에 오는지 적는다.
3. **비우기가 필요한가**: V1 성공 − V4 성공 ≥ 10 → "다 해 본 뒤에도 다시 시도하게 해야 한다".
4. **가림**: V1 성공과 V6 성공의 차이, 가림 걸음의 비율을 적는다. V6 성공 − V1 성공 ≥ 10 → "관측 key가 가림 때문에 손해를 본다", 그 밖 → "이 과제들에서는 가림이 드물거나 해롭지 않다".
5. **망가뜨린 판**: 변형마다 수를 그대로 적는다. V7이 V0에서 성공하던 판을 몇 판 망가뜨리는지, V2 · V3 · V4 · V5 · V6이 0인지.

1~3에서 "그 밖"이 차이가 음수(변형이 V1보다 나음)인 경우도 같은 문장으로 적고 차이 값을 함께 쓴다(문장은 바꾸지 않는다).
약한 모델(N=100)은 같은 표를 따로 적되 읽기는 "기준 모델과 같은 방향(차이의 부호)인가"만.

## 6. 보고

선언 · 결과 커밋 해시. 과제마다 표: 변형 × {성공, 2배 안, 살린 / 망가뜨린, 개입 수}, 기준 모델 세 seed와 평균, 약한 모델. 읽기 다섯 줄. 가림 세기 표. 한 것 / 안 한 것 / 추정.
순서: GoToLocal 먼저, PutNextLocal 다음. 보고하고 멈춘다.
