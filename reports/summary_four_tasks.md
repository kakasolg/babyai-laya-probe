# 네 과제 정리 — 작은 판단 모델(Laya)에 판단을 어디까지 맡길 수 있나 (2026-11-16)

[cloud]가 커밋된 보고서의 숫자로 썼다. 새로 돌린 것은 없다. 과제별 자세한 내용은 각 보고서에 있다:
`summary_gotolocal.md` · `stage6.md`(GoToLocal), `stage8.md` · `stage8d.md`(PickupDist), `stage9.md`(물건 16개), `stage10.md` · `stage10e.md`(옮겨 놓기).

## 1. 물은 것

MoKa가 처음에 적은 것(보드 11-15): 최종적으로 알고 싶은 것은 "이 과제를 외웠는가"보다 **"작은 모델에 판단을 맡기는 접근이 어느 정도까지 가능한가"**다.
BabyAI에서의 성공을 DSR · 트레이드 · 드론에서의 성공으로 확대 해석하지 않는다.

지킨 원칙: 한 번에 과제 하나, 환경 코드는 고치지 않는다, 정답은 봇에서만, 학습 · 개발용 · 최종 seed 분리, 최종 판은 판정 기준을 먼저 커밋한 뒤 한 번만.

## 2. 네 과제

모두 MiniGrid 3.2.0의 BabyAI 과제이고 방은 하나다. 모델은 Laya english `55cf4c4`(421M), 과제마다 봇 시범 약 1,000판으로 미세조정(학습 seed 0 · 1 · 2).
입력은 앞쪽 7×7 부분 관측을 글로 바꾼 것 + 지시문. 기억(지난 걸음)은 넣지 않았다.

|---|---|---|---|---|
| GoToLocal | 기준. 물체 8개 중 지시한 것 앞에 선다 | 3 (왼쪽 · 오른쪽 · 전진) | 998판 5,310걸음 | 64 |
| PickupDist | 줍기 추가. 틀린 것을 주우면 되돌릴 수 없다 | 4 (+ 줍기) | 990판 4,842걸음 | 49 |
| GoToLocal 물건 16개 | 길이 막힌다(300판 중 121판이 돌아가야 함) | 3 | 989판 5,308걸음 | 64 |

## 3. 핵심 표 (분모 300판, 성공 / 봇 걸음 2배 안 성공)

"2배 안" = 봇이 같은 판에 쓴 걸음 수의 2배 안에 성공. 헤매다 끝낸 판을 걸러 낸다(MoKa: 헤맨다는 것은 dsr로 치면 HP가 깎이는 것이라 횟수도 본다).

| | GoToLocal (최종 20000~) | PickupDist (최종 30000~) | 물건 16개 (**개발용** 10000~) | 옮겨 놓기 (최종 70000~) |
|---|---|---|---|---|
| 봇 | 300 / 300 | 300 / 300 | 300 / 300 | 300 / 300 |
| 무작위 | 138 / 25 | 53 / 9 | 132 / 24 | 0 / 0 |
| 모델 없음 + R-reset | 227 / 66 | 9 / 0 | 191 / 54 | 0 / 0 |
| **Laya 단독** s0 · s1 · s2 | 264 · 262 · 262 / 258 · 261 · 256 | 270 · 275 · 274 / 268 · 273 · 273 | 265 · 264 · 274 / 261 · 262 · 268 | 253 · 258 · 256 / 253 · 258 · 256 |
| **Laya + R-reset** | 296 · 296 · 295 / 278 · 285 · 270 | 289 · 293 · 292 / 285 · 290 · 288 | 297 · 297 · 296 / 279 · 285 · 283 | 298 · 299 · 298 / 288 · 292 · 293 |
| R-reset이 망가뜨린 판 | 0 | 0 | 0 | 0 |
| 걸음 단위 봇 일치 (개발용 판) | 94.7~95.7 % | 95.2~95.8 % | 94.9~95.8 % | 94.3~94.9 % |

- 과제가 달라 열끼리의 우열 비교가 아니다. 물건 16개는 최종 판(60000~60299)을 열지 않았다.
- **R-reset**: 한 판 안에서 같은 상태 글을 다시 만나면 거기서 이미 해 본 행동을 빼고 다음 순위를 고른다. 다 해 봤으면 그 상태의 기록만 비운다. 조절값이 없다. 모델 밖의 실행기 규칙이다.

|---|---|---|
| GoToLocal (6단계) | Laya 단독 264~288판 / 규칙 효과 | 단독 **미달**(262판 둘, 2판씩 모자람) / 규칙 효과 재현 |

| 옮겨 놓기 (10e) | 단독 2배 안 평균 ≥ 233 (구간 ≥ 240) / 규칙 ≥ 285 · 망가뜨린 판 0 | 둘 다 통과 (평균 255.7, 구간 유지 / 298 이상) |

## 4. 네 과제에서 같았던 것

1. **Laya 단독으로 84~91 %를 끝낸다.** 과제가 어려워져도(선택지 3 → 5, 한 단계 → 두 단계) 이 범위에서 크게 움직이지 않았다.
2. **모델 없이는 과제가 어려워질수록 0에 가까워진다**(모델 없음 + 규칙: 227 → 191 → 9 → 0판). 뒤의 두 과제에서 성공은 거의 전부 모델의 몫이다.
3. **규칙을 붙이면 96~99 %가 되고, 한 판도 망가뜨리지 않았다.** 네 과제 × 세 seed 모두.
4. **Laya는 "거의 맞게" 틀린다.** 규칙이 살린 판의 대부분이 2배 안에 끝난다(예: 옮겨 놓기 살린 41~45판 중 34~37판). 모델 없는 규칙은 성공을 올려도 2배 안은 못 올린다(GoToLocal 227판 중 66판).
5. **실패의 모양이 같다 — 판단이 아니라 이동.** 같은 자리에서의 반복(막힌 칸으로 전진, 좌우 번갈아 돌기)이고, 목표가 처음에 안 보이는 판과 길이 막힌 판에 몰려 있다.
   - 옮겨 놓기: 틀린 물체를 주운 적 0번(개발용), 줍는 · 내려놓는 걸음 일치 99~100 %, 들고 이동 88.7~90.5 %.
   - PickupDist: 앞이 비었을 때 줍기 0번, 틀린 물체를 스스로 주운 것 0~2번.
6. **걸음 단위 일치율(약 95 %)만으로는 닫힌 루프 성공을 알 수 없다.** 한 걸음의 실수가 반복으로 굳기 때문이다.

## 5. 과제마다 달랐던 것

- **옮김(9a)**: 물건 8개로 배운 모델을 16개 방에 그대로 쓰면 혼자 성공이 20~28판 준다(276 · 278 · 273 → 248 · 258 · 245). 989판으로 다시 배우면 회복된다. 배운 설정 밖으로는 완전히 옮겨지지 않는다.
- **규칙이 고른 행동의 위험**: PickupDist에서는 규칙이 줍기를 골라 틀린 물체를 줍는 일이 7~12판 있었다. 모두 규칙 없이도 실패하던 판이라 망가뜨린 판은 아니지만, 실패의 모양이 timeout에서 틀린 줍기로 바뀌었다. 되돌릴 수 없는 행동이 있는 과제에서는 "안 해 본 행동을 해 본다"가 공짜가 아니다.
- **입력 한 줄의 값**: 옮겨 놓기에서 "들고 있는 것" 줄을 빼면 2배 안 성공이 개발용 15판, 최종 28판 낮고, 들지 않은 채 내려놓기를 고른 헛동작이 0 → 5,160 · 5,789번이 된다. 학습 한 번의 결과다. (10단계 선언은 "15판 넘게", 10e 선언은 "15판 이상"으로 문구가 달랐다 — [cloud]의 실수.)
- **봇이 선택지 밖의 행동을 쓰는 판**: PickupDist에 내려놓기를 쓰는 판이 있어(개발용 2, 최종 2) 네 선택지로는 풀 수 없었다.

## 6. 처음 목표 넷에 비추어

| 도달 목표 | 네 과제를 지난 뒤의 답 |
|---|---|
| 1. 관측과 지시를 받아 다음 행동을 고른다 | 된다. 네 과제 모두 봇과 약 95 % 일치. |
| 2. 이어서 실행해 새 배치에서 과제를 끝낸다 | 혼자 84~91 %, 실행기 규칙과 함께 96~99 %. 최종 판에서 세 과제 확인. |
| 3. 한 걸음씩 사람이 확인 · 교정할 수 있다 | 글자판과 게임(Godot)으로 만들었다. 이후 게임은 자율주행 · 퍼즐 화면으로 이어졌다(`godot/drive/README.md`, `PUZZLE.md` — 실시간 운전은 Laya가 아닌 작은 신경망). |
| 4. 실패하면 무엇을 고쳐야 할지 작은 비교로 본다 | 아래 표. |

| 무엇을 | 한 비교 | 본 것 |
|---|---|---|
| 입력 정보 | 지시문 가림 · 바꿔치기(GoToLocal), "들고 있는 것" 줄 빼기(옮겨 놓기) | 지시문은 쓰인다(바꿔치기 때 선택이 따라 바뀜 80.2 %, 평소 일치 89.3 %보다 9 %p 낮은 이유는 못 밝힘). 들고 있는 것은 필요한 정보로 보인다. |
| 실패 구조 | A/B/C 분류(GoToLocal), 어디까지 갔나 ① ~ ④(옮겨 놓기) | 현재 입력에 단서가 있는데 잘못 고른 것이 가장 많고, 그다음이 안 보일 때의 탐색 반복. |
| 실행기 | 규칙 R(포기 있음) · R-reset · 방문 벌점 · 무작위 섞기 | R-reset이 기본. 무작위로 섞는 방식은 잘 되던 판을 망가뜨렸다. |
| 학습 없는 모델 | Jev · Gemma 12B(GoToLocal) | 혼자 163 · 111판, 규칙과 함께 282 · 280판. 봇 길 위 막힌 걸음에서 전진을 고른 비율: Laya 0~0.8 %, Jev 5.2 %, Gemma 22.5 %. |
| 배운 것의 옮김 | 물건 8 → 16 그대로 / 다시 학습 | 그대로는 떨어지고 다시 배우면 회복. |

**하지 않은 비교**: 전체 관측, 그림 입력, 지난 걸음(이력) 입력, 학습 자료의 양(Laya로는 약 1,000판 한 점뿐), 여러 방 과제(문 · 열쇠), 강화학습.

## 7. 한계

- 방 하나, 지시 한 줄짜리 과제다. 기억이 꼭 필요한 과제(여러 방, 문 · 열쇠)는 하지 않았다. 남은 실패가 "안 보일 때"에 몰려 있으니 그런 과제에서는 더 떨어질 것으로 본다(추정).
- 학습 자료의 양을 바꿔 본 적이 없다. "1,000판이면 된다"가 아니라 "1,000판으로 이만큼 됐다"다.
- 최종 판은 과제마다 300판 한 묶음이다. GoToLocal에서 개발용과 최종이 12~16판 달랐다 — 300판의 흔들림이 그 정도다.
- 물건 16개는 개발용 판 숫자다.
- 학습 seed 셋은 같은 자료 위의 셋이다. 자료를 바꿔 본 것이 아니다.
- 지시문 바꿔치기의 9 %p 차이는 설명하지 못했다.

## 8. 저장소 밖 참고 (이 저장소의 실험이 아니다)

- **작은 전용 신경망**([cloud], CPU, FiLM을 쓴 CNN 약 6만 파라미터): GoToLocal에서 시범 998판으로 197~251판, 1만 판으로 284~292판. 시범을 10배 주면 Laya 단독을 넘는다. 봇이 시범을 얼마든지 만들어 주는 환경에서는 Laya의 이점이 "시범이 적을 때"로 좁혀진다. 게임의 자율주행 등급 1 · 2 · 3이 이 신경망이다(`tools/small_policy/`, `godot/data/policy_l*.json`).
- 같은 신경망을 11-16에 한 번씩 돌린 미리 보기(시범 2,000판, 보드 c7d1bc74): 물건 16개 166판(2배 안 135), 옮겨 놓기 69판(61). Laya는 그 절반의 시범으로 264~274판, 253~258판이었다. 조건이 달라(시범 수, 평가 판, 한 번 실행) 엄밀한 비교는 아니지만, 과제가 어려워질수록 격차가 벌어지는 방향이다.
- **dsr-bot에 옮겨 본 것**(보드 c83f86f4 · c4a93727): 싸움 결정 기록 20,658개에 작은 신경망을 붙였더니 규칙 따라 하기 63.9 %("직전 결정 베끼기" 69.4 %보다 낮음), 피격 예측은 찍는 수준이었다. 기록에 규칙이 쓰는 정보(애니 경과 시간 등)가 없고 맞은 사례가 적어서다. 거기서는 게임 파일에서 뽑은 표(판정 시각, 회전이 막히는 구간)가 먼저 통했다. "같은 입력 → 같은 선택"의 반복도 dsr-bot에서는 실행당 0.05건으로 드물었다. → 확대 해석하지 않는다는 처음 원칙 그대로다.

## 9. 한 문단 답

상태를 글로 적어 주고 선택지가 서너 개에서 다섯 개인 방 하나짜리 과제에서는, 시범 약 천 판으로 미세조정한 작은 판단 모델이 새 배치의 열에 여덟아홉을 혼자, 봇과 비슷한 걸음 수로 끝낸다. 두 단계짜리 과제까지 그랬다. 나머지는 모델을 키우지 않고도, 같은 상황의 반복을 바깥에서 잡아 다음 순위를 고르게 하는 규칙 하나로 대부분 풀렸고, 그 규칙은 잘 되던 판을 한 번도 망가뜨리지 않았다. 모델이 틀리는 곳은 "무엇을 할지"가 아니라 "막혔을 때 어떻게 움직일지"였다. 이것은 방 하나짜리 BabyAI 안에서의 결론이다.
