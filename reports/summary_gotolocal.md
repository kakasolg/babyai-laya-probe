# GoToLocal 정리 — 작은 판단 모델(Laya)에 길 찾기 판단을 맡겨 보기 (2026-11-15)

- **과제**: `BabyAI-GoToLocal-v0`이다. 8×8 방 하나에 물체 8개가 있고, 지시문은 "go to the red ball" 꼴이다.
- **입력**: 에이전트 앞쪽 7×7 부분 관측을 글로 바꾼 것과 지시문을 준다.
- **선택지**: 왼쪽 돌기 / 오른쪽 돌기 / 전진, 세 개다.
- **모델과 학습**: Laya english `55cf4c4`(421M)를 봇 시범 998판(5,310걸음)으로 약 5분 미세조정했다. 학습 seed는 0·1·2다.
- **판정**: 성공 판정은 환경이 한다. 걸음 제한은 64다.

## 1. 무엇을 물었나 — 처음 목표 넷과 답

MoKa가 실험을 시작하며 적은 도달 목표 넷이다(보드 11-15).

| 도달 목표 | 답 한 줄 | 근거 |
|---|---|---|
| 1. BabyAI의 간단한 과제 하나에서 모델이 관측과 지시를 받아 다음 행동을 선택한다. | 된다. 봇 궤적 위에서 봇과 일치하는 비율이 94.7~95.7 %다. 선택지 순서만 바꿔 답이 바뀌는 비율은 0.4~1.5 %다. 학습 없는 제로샷은 각각 56.9 %, 57.9 %였다. | [stage3.md](stage3.md), [stage3_5.md](stage3_5.md) §1 |
| 2. 한 장면의 정답률뿐 아니라, 행동을 이어서 실행하여 새로운 배치에서도 과제를 끝내는지 확인한다. | 대체로 끝낸다. Laya 단독 성공은 개발용 판에서 91~93 %, 선언 뒤 처음 쓴 최종 판에서 87~88 %다(미리 정한 기준에는 미달). 실행기 규칙 R-reset을 붙이면 두 묶음 모두 98~99 %이고, 망가뜨린 판은 0이다. 실패는 거의 다 같은 상태에서 같은 선택을 반복한 것이다(아래 3). | [stage5.md](stage5.md), [stage6.md](stage6.md) |
| 3. 필요할 때 한 단계씩 진행하면서 MoKa가 모델의 선택을 확인하고 다른 행동으로 교정할 수 있게 한다. | 만들었다. 글자판과 게임(Godot) 두 가지다. MoKa가 첫 바퀴로 12판을 교정해 모두 성공했다(교정 65번). 원인 메모(1/2/3)는 0개라 원인 비율은 아직 없다. | [stage4.md](stage4.md), README "교정 루프" |
| 4. 실패하면 입력 정보 부족, 상태 표현, 학습 데이터, 모델의 선택 능력 중 무엇을 개선해야 할지 작은 비교로 확인한다. | 아래 두 줄로 나눈다. | — |

목표 4 — **이 저장소에서 한 비교**:
- 입력 정보: 지시문 가림과 지시문 바꿔치기를 했다(아래 4).
- 실패 구조: A/B/C 분류를 했다. 가장 큰 몫은 현재 입력에 단서가 있는데 잘못 고른 A다.
- 실행기 쪽: 규칙 R, R-reset, 방문 벌점을 비교했다.
- 막힌 걸음의 forward 비율을 봇 궤적과 스스로 걸은 길에서 따로 쟀다(아래 3).
- 학습 없는 모델(Jev · Gemma)을 참조선으로 돌렸다(아래 5).
- 모델의 선택 능력은 **이 저장소의 실험에서는 직접 비교하지 않았다**. 근거로 든 것은 봇 궤적 위 막힌 걸음의 forward 비율과 Jev · Gemma 참조선뿐이다. 저장소 밖 참고 단락(맨 아래)에 구조와 시범 양을 바꾼 비교가 있으나, 입력 형식이 달라 엄밀하지 않다.

목표 4 — **하지 않은 비교**:
- 전체 관측(부분 관측 대신 방 전체)
- 글 표현 바꾸기(그림 입력, 이력 입력 포함)
- 학습 데이터 양·구조(위의 저장소 밖 참고 단락을 가리키기만 함)

최종적으로 알고 싶은 것은 "이 과제를 외웠는가"보다 "작은 모델에 판단을 맡기는 접근이 어느 정도까지 가능한가"다. BabyAI에서의 성공을 DSR · 트레이드 · 드론에서의 성공으로 확대 해석하지 않는다.

## 2. 핵심 표 (분모 300판, "2배 안" = 봇이 같은 판에 쓴 걸음 수의 2배 안에 성공)

| 정책 | 개발용 10000~10299: 성공 / 2배 안 | 최종 20000~20299: 성공 / 2배 안 |
|---|---|---|
| 봇 | 300 / 300 | 300 / 300 |
| 무작위 | 135 / 22 | 138 / 25 |
| 모델 없음(고정 점수 forward > left > right) + R-reset | 198 / 51 | 227 / 66 |
| Laya 단독 s0 / s1 / s2 | 276 / 278 / 273 · 271 / 278 / 265 | 264 / 262 / 262 · 258 / 261 / 256 |
| Laya + R-reset s0 / s1 / s2 | 297 / 298 / 295 · 288 / 295 / 276 | 296 / 296 / 295 · 278 / 285 / 270 |

- **R-reset**: 한 판 안에서 같은 상태 글을 다시 만나면 거기서 이미 해 본 행동을 빼고 다음 순위를 고른다. 세 행동을 다 해 봤으면 그 상태의 기록만 비운다. 조절값이 없고, 앞으로 기본 규칙이다.
- 최종 판은 선언(`eea7aa4`)을 커밋한 뒤 한 번만 돌렸다.
  - **규칙 효과는 재현**됐다. 295판 이상이고, 규칙 때문에 망가진 판은 0이다.
  - **Laya 단독은 미리 정한 기준(264~288판)에 미달**이다. s1·s2가 262판으로 2판씩 모자란다.
  - 개발용 판과 최종 판 600판을 합치면 Laya 단독 성공은 약 90 %다. 학습은 개발용 판을 보기 전에 끝났으므로, 300판 표본의 흔들림일 가능성이 크다.
- 규칙만으로도 227판이 풀린다. 그러니 성공 수만 보면 안 되고, 판단의 질은 2배 안 성공에서 갈린다. 모델 없음은 66판, Laya + 규칙은 270~285판이다.

## 3. 왜 실패하나

- 실패는 거의 다 반복이다. 하나는 **막힌 칸으로 계속 전진**하는 것이고, 다른 하나는 **좌우로 번갈아 도는** 것이다.
  - 개발용 판 실패를 A/B/C로 나눴다(`stage3_5.md`).
  - A가 가장 많다. A는 현재 입력에 단서가 있는데(막은 것이 `1 ahead`로 보임) 잘못 고른 경우다.
  - B는 seed마다 7~8판이다. B는 대상이 안 보이는 상태에서 탐색을 반복한 경우다.
- 앞 칸이 막힌 걸음에서 1순위가 forward인 비율이 상황에 따라 크게 다르다.
  - 봇이 걸은 길 위에서는 249걸음 중 **Laya 0~0.8 %** 다. Jev는 5.2 %, Gemma는 22.5 %다.
  - Laya가 스스로 걸은 길에서는 **52~77 %** 다. 이 숫자는 반복에 빠진 판이 걸음 수를 채운 것이다.
- 해석(**추정**): 원인은 입력 정보나 선택 능력이 아니라 **시범이 덮지 못한 상태**다. Laya는 봇이 가는 상태에서는 막힘을 가장 잘 지킨다. 한 번 시범 밖 상태로 걸어 들어가면 거기서 반복한다. 상태 분포는 세지 않았다.

## 4. 지시문을 쓰는가

- **지시문 가림**: 지시문 줄을 `mission: (hidden)`으로 바꾸면 성공이 0.7 %로 떨어진다.
  - 거의 모든 판이 좌우 왕복이다. 지시문 줄에 의존한다는 데까지만 말할 수 있다.
  - 학습 때 본 적 없는 입력이라 무너진 것과 섞여 있어서, **약한 근거**다.
- **지시문 바꿔치기**: 같은 방에서 지시문만 다른 물체로 바꾸면 바꾼 대상에 닿는 판이 80.2 %다. 같은 197판을 원래 지시문으로 걸으면 89.3 %다.
  - 지시문을 읽고 대상을 고른다는 증거로는 가림보다 강하다.
  - **차이 9.1 %p의 원인은 미확인**이다. "바꾼 대상이 덜 보여서"라는 설명으로는 약 1.4 %p만 설명된다.

## 5. 참조선 — 학습 없는 모델 (개발용 판만)

| | 성공 / 2배 안 (규칙 없음) | 성공 / 2배 안 (R-reset) | 걸음 단위 봇 일치 · 순서 바꿔 답이 바뀜 |
|---|---|---|---|
| Jev `jev-1.14.0` | 163 / 158 | 282 / 214 | 69.2 % · 9.6 % |
| Gemma 12B (`gemma4:12b-it-q8_0`) | 111 / 106 | 280 / 163 | 66.9 % · 21.9 % |

- 두 모델에 준 설명은 호출 전에 확정했다(README "5단계").
- Gemma는 약한 참조선이다.
  - 실제로 낸 첫 토큰의 56.8 %가 숫자가 아니라 문장 시작이었다. 점수는 숫자 토큰 확률로 계산했다.
  - 대상이 안 보이는 걸음에서 봇과 일치하는 비율이 26.6 %로, 무작위(33 %)보다 낮다.
- 규칙이 성공 수를 크게 올리지만, 2배 안 성공은 덜 오른다. 규칙이 일을 상당 부분 한 것이다.
- 학습 여부가 다르므로 Laya와의 우열로 요약하지 않는다. 최종 판에서는 돌리지 않았다.

## 6. 잘못 읽었다가 고친 것

- "실패는 기억이 없어서" → 실패 중 가장 큰 몫은 현재 입력에 단서가 있는데 잘못 고른 A였다(`stage3_5.md`).
- "걸음 단위 상한 ≈ 99.25 %" → 상한이 아니다. 입력이 거의 다 한 번씩만 나와서 생긴 숫자다(`stage1.md`).
- 평균 걸음 "5.33 vs 5.22" → 분모가 달랐다. 같은 276판에서 봇은 4.87걸음이다(`stage3.md`).
- 보정 조각 정확도 0.945 → 독립 평가가 아니다. 학습 판의 앞뒤 걸음이 섞여 있다.
- "틀린 물체 앞에서 끝" 열 → 실패 유형이 아니다. 걸음 제한에 걸린 순간의 위치일 뿐이다.
- "지시문 가림 0.7 % → 지시문을 쓴다" → "지시문 줄에 의존한다"까지만 말할 수 있다.
- 바꿔치기 차이에 대한 보드 글의 "약 7.7 %p" → 이 저장소 숫자로는 9.1 %p다.
- 바꿔치기 차이를 "바꾼 대상이 덜 보여서"로 본 것 → 대부분 틀렸다. 그 설명은 약 1.4 %p뿐이다(`stage4.md` §6).
- "Jev는 막힌 전진이 적다 → Laya 실패는 학습 쪽" → 보류했다. 봇이 걸은 길 위에서는 Laya가 막힘을 가장 잘 지킨다(`stage5.md` §5).
- "방문 벌점이 R-reset보다 낫다"(개발용 판에서 0~3판 많음) → 최종 판에서 사라졌다(295 / 294 / 295 vs 296 / 296 / 295).
- 개발용 판 98~100 %대 숫자 → 규칙을 만들 때 본 판이라 일반화 성능이 아니다. 최종 판으로 다시 쟀다(`stage6.md`).

## 7. 이 결과가 말하지 않는 것

- 방 하나짜리 길 찾기, 기억이 필요 없는 짧은 과제(봇 평균 약 5걸음), 부분 관측을 글로 바꾼 입력에만 한정된다.
- 더 큰 방, 여러 방, 기억이 필요한 과제, 속도는 재지 않았다.
- DSR · 트레이드 · 드론 등 BabyAI 밖으로 넓혀 읽지 않는다. 격자 과제는 입력이 글자 그대로 같으면 같은 상황이고, 더 시도해도 잃는 것이 걸음 수뿐이다.

## 참고 — 저장소에 코드 없음, Laya 아님

[cloud]가 저장소 밖에서 CPU로 작은 모델을 돌려 잰 것이다. 이 저장소에서 다시 재지 않았다.
- 같은 998판으로 학습했을 때, 펼친 신경망은 42~47 %였다. 지시문 조건부 작은 합성곱망(92만 파라미터)은 75~84 %였다.
- 시범을 1만 판으로 늘리면 합성곱망이 95~97 %가 됐다. 규칙을 붙이면 300/300이었다.
- 직전 행동을 입력에 넣은 효과는 998판에서는 없었다. 1만 판에서는 292 vs 284판이었다(seed 하나).
- 스스로 걸은 상태에 봇의 답을 달아 새 방 1,000개를 더했다. 막힌 전진이 낀 실패는 19~27판에서 4~6판으로 줄었다. 하지만 전체 성공(257~264판)은 같은 방의 일반 시범을 추가한 경우(262~272판)와 차이가 없었다.
- 무작위 섞기(ε-greedy · softmax)는 잘 되던 판을 망가뜨렸다.
